# Provenance

Where each module of java-compat-rs comes from: what was consulted to write it, where its data comes from, and the
licence that material carries. Established 2026-10-28 by comparing every code module with
the OpenJDK 21.0.11 sources (`lib/src.zip` of a local JDK) and by reading the `reference/` generators, their fixtures
and the JDKs' own `legal/` notices. It records the state of commit `00078f4`.

## Summary

- **Translated from OpenJDK source.** None any more. The last such module (`util/calendar.rs`, which followed
  OpenJDK's private `GregorianCalendar` implementation method by method) was rewritten clean-room on 2026-10-28
 . See [Translated modules](#translated-modules).
- **Reimplemented from observed behaviour.** The other code modules are written from the Java SE API documentation and
  from output recorded in real JDKs (`reference/src/*.java` -> `tests/fixtures/`), or port Apache Commons (Apache-2.0).
- **Generated and hand-copied tables.** Locale tables are CLDR data as the JDK exposes it (Unicode licences); the
  EUC-JP/Big5 table is generated from Unicode's mapping files (Unicode-3.0), checked against OpenJDK's encoders;
  currency codes are ISO 4217 facts with CLDR symbols.
- The README's "`upstream/` is the original source, pinned to the ported release" is not true: the repository has no
  `upstream/` directory or submodule in any commit (the skeleton commit `163bda1` says so in its subject only). The
  README's and `locale.rs`'s "CLDR 42" for Keycloak 26.5.3's JDK 21 is also off: that JDK (Red Hat 21.0.10) declares
  CLDR v43 in `legal/jdk.localedata/cldr.md`.

## Test material

- `tests/fixtures/**` are outputs recorded from JDK 26 (eclipse-temurin), the MockServer 8.0.0 image's trimmed JDK
  and Keycloak 26.5.3's JDK 21 by `reference/src/*.java` (written for this crate); they inherit the tables' data
  licences above where they hold locale data.
- `reference/src/OpenJdkCases.java` re-creates inputs of classic OpenJDK regression tests (JBS bug ids such as
  4125885 with their pattern and value) as single input-to-output checks; no OpenJDK test code is copied and the
  expected outputs are recorded from the JDK.

## Translated modules

No module is translated from OpenJDK source any more.

`util/calendar.rs` was rewritten clean-room on 2026-10-28: from the Java SE API documentation of `Calendar` and `GregorianCalendar`, the recorded fixtures and new observations of an arm64 `eclipse-temurin:21-jdk` (JDK 21.0.12.1), without opening OpenJDK source or the replaced file (its git history included); its row above says what was used. Until then it followed OpenJDK's private methods (`getFixedDate`, `getFixedDateMonth1`, `actualMonthLength`, `computeFields`/`computeTime`) and was a derivative work of OpenJDK (`GPL-2.0-only WITH Classpath-exception-2.0`).

`text/digits.rs` and `text/decimal.rs` were rewritten clean-room on 2026-10-28: from the Java SE API documentation, the fixtures above and new jshell observations on an arm64 `eclipse-temurin:21-jdk`, without opening OpenJDK source or the replaced files; their rows above say what was used.

`text/message.rs` was rewritten clean-room on 2026-10-28: from the Java SE API documentation of `MessageFormat` and `ChoiceFormat`, the recorded fixtures and new observations of an arm64 `eclipse-temurin:21-jdk` (JDK 21.0.12.1), without opening OpenJDK source or the replaced file; its row above says what was used.

`text/date_format.rs` was rewritten clean-room on 2026-10-28: from the Java SE API documentation of `SimpleDateFormat` and `DateFormat`, the recorded fixtures and new observations of an arm64 `eclipse-temurin:21-jdk` (JDK 21.0.12.1), without opening OpenJDK source or the replaced file; it uses `util/calendar.rs` through its public signatures only; its row above says what was used.

`text/formatter.rs` was rewritten clean-room on 2026-10-28: from the Java SE API documentation of `Formatter`, the recorded fixtures and new observations of an arm64 `eclipse-temurin:21-jdk` (JDK 21.0.12.1), without opening OpenJDK source or the replaced file; its row above says what was used.

`regex.rs` was rewritten clean-room on 2026-10-28: from the Java SE API documentation, `tests/fixtures/jdk21/regex.json` and new observations of an arm64 `eclipse-temurin:21-jdk` (JDK 21.0.12.1), without opening OpenJDK source or the replaced file; its Unicode tables (`src/regex/tables.rs`) are generated by `src/regex/RegexTables.java` from that JDK's public API and observed `\p{..}` and case-insensitive matching.

## freemarker-rs

freemarker-rs (Apache FreeMarker 2.3.32 port, upstream ASF Apache-2.0 pinned as its `upstream` submodule) is clean:
its NOTICE names FreeMarker and the ASF correctly, and no OpenJDK source was translated in it; its Java regex and
date behaviour come from java-compat-rs (the regex module moved here in `f50161f`, where `RemoveQEQuoting` first
appears; freemarker-rs's history has none of the translated methods).
